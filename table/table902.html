gotify 工具 go语言编写的小型简单信息通知工具 #自定义配置启动（端口、数据库路径等）
#如果你想改端口或指定数据库位置，Gotify 现在用的是环境变量，而不是旧的 YAML 配置文件。可以用 GOTIFY_ 前缀来设置：
# 示例：把端口改成 8080，数据库放到 /var/lib/gotify/gotify.db
GOTIFY_SERVER_PORT=8080 \
GOTIFY_DATABASE_DIALECT=sqlite3 \
GOTIFY_DATABASE_CONNECTION=/var/lib/gotify/gotify.db \
./gotify-linux-amd64 serve

#Gotify 的默认账号和密码都是 admin
#如果你在启动时通过环境变量 GOTIFY_DEFAULTUSER_PASS 指定了密码，那默认密码就会被覆盖成你设置的那个，但用户名依然是 admin

#外部脚本监听 WebSocket
#Gotify 暴露了一个 WebSocket 端点（/stream），任何语言写的程序都能连上去实时接收消息，处理后再转发
websocat 'ws://127.0.0.1:8080/stream?token=CLIENT_Token'

#Gotify 目前不支持将管理页面和数据接口拆分到不同端口
#反向代理做访问控制
Nginx 方案示例：将 Gotify 自身绑定在 127.0.0.1:8080（仅本机可访问），然后通过 Nginx 暴露出去。
#可以针对 /message（发送接口）和 /stream（WebSocket）放行外部访问，而对根路径 /（管理页面）限制为仅内网 IP 可访问：
#Gotify 的 GOTIFY_SERVER_LISTENADDR 需要设置为 127.0.0.1
location = /message {
proxy_pass http://127.0.0.1:8080;
# 允许所有来源访问发送接口
allow all;
}

location /stream {
proxy_pass http://127.0.0.1:8080;
# WebSocket 需要的头部
proxy_http_version 1.1;
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
allow all;
}

location / {
proxy_pass http://127.0.0.1:8080;
# 管理页面仅允许内网访问
allow 192.168.1.0/24;
deny all;
}


client和app有什么关系
Gotify 的数据模型是：User 拥有 App，User 也拥有 Client，谁创建的就是谁的，一个用户创建的app和client是互通的。
App：属于某个 User，只能发送消息。
Client：属于某个 User，只能接收消息和进行管理操作

使用curl向gotify发送信息

curl -s -S \
-H 'Content-Type: application/json' \
-H "X-Gotify-Key: APPToken" \
"http://127.0.0.1:8080/message" \
-d @- <<_EOF
{
"message": "Hello:man ![](https://gotify.net/img/logo.png)",
"title": "My Title OK",
"priority": 5,
"extras": {"client::display": {"contentType": "text/markdown"}}
}'
_EOF
#Gotify 的 client::display 仅支持 text/plain（默认）和 text/markdown 两种格式，text/html 不在支持范围内
