named.conf 缓存 缓存时间和内存控制 named缓存时间和内存控制 options { # 设置缓存最大容量 # 可以使用具体的数值（字节），也可以使用百分比 max-cache-size 512M; # 如果你想让它占用总内存的 50% # max-cache-size 50%; # 清理缓存的阈值（可选） # 当缓存达到 max-cache-size 时，BIND 会开始丢弃旧记录 }; 参数说明 单位：支持 K (Kilobytes), M (Megabytes), G (Gigabytes)。 0 或 unlimited：表示不设限制（不推荐，除非内存极大）。 影响：增加缓存可以提高重复查询的响应速度，减少对 google.com 等转发域名的递归压力。 进阶优化：控制缓存的“寿命” (TTL) 仅仅增加缓存数量是不够的，如果记录的 TTL（生存时间）太短，缓存很快就会失效。你可以强制设置最大缓存时间： options { # 记录在缓存中保存的最长时间（秒） # 即使原始 DNS 说可以存 1 天，BIND 也会在 7200 秒后清理 max-cache-ttl 7200; 如果你想实现“保底”（强制延长缓存） 如果你觉得有些域名（比如 Gemini 的 API 地址）刷新太快，想让它们在缓存里多待一会儿，你需要的是另一个参数：min-cache-ttl。 # 强制所有记录至少缓存 1 小时 min-cache-ttl 3600; #配置了 min-cache-ttl 3600 后：即使 google.com 只给 60 秒的 TTL，你的 BIND 也会强行把它留住 3600 秒。经测试，ttl范围是0到90，否则配置文件报错 # 负面缓存时间（解析失败/不存在的域名保存多久） # 建议设短一点，防止 chatgpt.com 临时解析失败后卡很久 max-ncache-ttl 300; }; rndc dumpdb -cache
